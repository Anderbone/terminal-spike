## Findings considered and rejected

- **Backup export/restore contradicts its no-passphrase documentation** —
  rejected after tracing the live workflow. `SettingsBackupWorkflow` deliberately
  supplies app-defined portability material and bypasses the orphaned manual
  passphrase dialogs; README, security model, and backup-format docs explicitly
  state that this is authentication, not a confidentiality boundary. Removing
  the dead dialog code is optional cleanup, not a public-contract defect.
- **Create a second release-evidence manifest plan** — rejected as duplication.
  Plan 005 already freezes a content-sensitive source manifest, exact test
  reports, and artifact hashes; its final documentation reconciliation must make
  that one candidate record authoritative.
- **Create separate plans for clean-install backup, configuration/multi-window,
  TalkBack, and real-session endurance** — folded into Plan 005 rather than duplicating its
  explicit gates. Clean-install backup, physical orientation/maximum-text/split-window, and IME
  checks are green; physical TalkBack/OEM and extended acceptance remain open.
- **Require hosted real-Mosh CI before an SSH-only main-app release** — deferred.
  ADR-003 blocks public Mosh distribution pending legal/trademark/signing review;
  retain the guarded physical 5+1 gate for extension changes and revisit hosted
  UDP E2E only if extension distribution resumes.

- **Restore the old top-level Connections destination** — rejected. The later
  user requirement explicitly makes Terminal the second primary destination;
  Connections is a secondary catalog.
- **Restore badges, status controls, Back, or a large Connections button to the
  terminal header** — rejected. The later user requirement explicitly asks for
  short tab names and only a fixed `+` in the top strip. Plan 003 uses a context
  menu/bottom sheet instead.
- **Force every custom keyboard profile to the current default key count** —
  rejected as an over-reading. The default live deck is currently 20 keys in two
  rows of ten; custom layouts remain flexible unless product intent changes.
- **Mosh is fake or absent from source** — rejected. A genuine separately
  installed dual-ABI extension and real password-auth UDP round trip exist.
  Android transition-hint publication is now wired. Remaining work is broader
  device acceptance, extension-absent SSH evidence, install guidance, and the
  external public-distribution decision.
- **Move remote-session ownership back into ViewModels** — rejected.
  `SshSessionRepository` is application-owned and the foreground-service gate
  precedes transport startup.
- **Terminal selection, OSC 8, OSC 52, typed colours, or dirty-row parsing are
  absent** — rejected; current source implements those foundations. Dirty rows
  now cross the controller boundary and invalidate exact visible-row rectangles;
  the remaining Plan 005 gap is measured device performance, not wiring.
- **Snippet Insert is unavailable** — rejected for the current Connections path;
  it inserts into the buffered draft. An older compatibility handler still has
  stale wording but is not the active product route.
- **Delete detached saved passwords automatically on endpoint edit** — rejected.
  Current tests document the conservative no-data-loss retention policy; orphan
  cleanup needs a separate, explicit credential-lifecycle product decision.
- **Block completion on public Mosh distribution** — rejected for a local/debug
  or SSH-only app handoff. ADR-003 correctly treats public extension distribution
  as an external legal/signing decision; Plan 005 reports it distinctly.
- **Refactor the 4,700-line ViewModel before release** — deferred. The coupling
  is real, but a broad pre-release extraction has high regression risk and lower
  leverage than the concrete SFTP, CI, lifecycle, and accessibility gaps.
- **Delete the legacy Workspace island during this release-hardening pass** —
  deferred. It appears unreachable and should be characterized/removed later,
  but it is not currently a user-visible correctness or security blocker.
- **Use hosted-emulator timing as the navigation performance threshold** —
  rejected. Current physical Perfetto evidence is the meaningful baseline;
  arbitrary hosted-runner timing would be noisy and could hide real regressions.
